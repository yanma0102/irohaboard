## 7. 実施手順

### 7.1 移行前の実施手順

1. 現行環境（CakePHP 2.10 / PHP 8.1 / MySQL 5.7）を Docker で起動する
2. `docker compose up -d` でコンテナを起動し、ブラウザでアクセス可能であることを確認する
3. テストデータを投入する（受講者アカウント、管理者アカウント、コース、コンテンツ、問題）
4. 上記 §1〜§5 の各テストケースを順に実施する
5. 各テストケースの「移行前結果」欄に合格/不合格を記入する
6. 不合格の場合は備考欄に障害内容を記録する

### 7.2 移行後の実施手順

1. 移行後環境（CakePHP 5.x / PHP 8.4 / MariaDB 11.4）を Docker で起動する
2. `docker compose up -d` でコンテナを起動し、ブラウザでアクセス可能であることを確認する
3. 移行前と同じテストデータを使用する（DB 移行済みであること）
4. 上記 §1〜§5 の各テストケースを順に実施する
5. 各テストケースの「移行後結果」欄に合格/不合格を記入する
6. 不合格の場合は備考欄に障害内容を記録する

### 7.3 結果の突合

1. 全テストケースの実施が完了したら、「移行前結果」「移行後結果」の各欄を比較する
2. 一致する場合は「一致」欄に `✓` を記入する
3. 不一致の場合は「一致」欄に `✗` を記入し、備考欄に差分の詳細を記録する
4. 移行前は合格だが移行後は不合格のケースは、移行起因のバグとして優先的に修正対象とする

## 8. 判定方法

### 8.1 個別テストケースの判定基準

| 判定 | 条件 |
|---|---|
| **合格** | 操作手順を実行し、期待結果が得られた場合 |
| **不合格** | 操作手順を実行したが、期待結果が得られなかった場合 |
| **該当なし** | テスト環境の制約により実施不能の場合（備考にその理由を記載） |

### 8.2 移行成否の全体判定基準

| 判定 | 条件 |
|---|---|
| **移行成功** | 全 41 テストケースが合格し、移行前後で結果が全て一致する |
| **条件付き成功** | 不合格ケースが1件以上あるが、その全件が移行起因でない（既存バグ等） |
| **移行失敗** | 移行起因の不合格ケースが1件以上ある |

### 8.3 不合格時の対応フロー

1. 不合格ケースの障害を再現する
2. 障害の原因を特定する（移行起因 or 既存バグ or 環境起因）
3. 移行起因の場合：該当フェーズのコードを修正し、再テストを実施する
4. 既存バグの場合：備考に記録し、移行対象外とする
5. 環境起因の場合：環境設定を修正し、再テストを実施する
