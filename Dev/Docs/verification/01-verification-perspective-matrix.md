# 検証観点マトリクス（Verification Perspective Matrix）

> 上位: `README.md` / 項目: `02`〜`04` / E2E: `05` / リスク: `06`
> 作成日: 2026-09-25

本ドキュメントは「**何を・どの品質特性で・どの技法で検証するか**」を三次元で網羅する。マトリクスは計画の網羅性を保証する道具であり、空欄・偏りを検出するために使う。

---

## 1. 三次元モデル

```
        軸C: 技法（どう検証するか）
              ▲
              │   EQ BV DT ST PW UC EG EX AB PB FZ RG SM CH PF
              │
              │        ┌───────────────────────────────┐
              │        │  ◎ = 重点  ○ = 標準  △ = 限定的 │
              │        │  − = 対象外・軽微              │
              │        └───────────────────────────────┘
              │
  軸B: 対象領域 ─────────────────────────────► 軸A: 品質特性
  （T01〜T17）                                   （F D A Z V E S I U Y P R O M）
```

## 2. 軸 A: 品質特性（検証観点）

| コード | 品質特性 | 定義 | 代表的な失敗モード | 主オラクル | 機械化 |
|---|---|---|---|---|---|
| **F** | 機能適合性 | 仕様どおりの機能が正しく動作する | ロジック誤り、リンク切れ、誤遷移、表示欠落 | 設計書 / 旧実装 | ◎ |
| **D** | データ整合性 | 永続化・更新・集計・削除が正しく一貫する | 集計ズレ、孤児レコード、文字化け、半端な更新 | DB スキーマ / 集計仕様 | ◎ |
| **A** | 認証・セッション | 本人性の確立と継続が正しい | セッション固定、失効漏れ、Cookie 不備、旧パスワード互換破綻 | 認証設計 | ○ |
| **Z** | 権限・認可 | ロール/登録境界が破られない | 水平/垂直の権限昇格、非公開の漏洩、CSV 経由の権限操作 | 権限マトリクス | ○（濫用は非機械） |
| **V** | 入力検証・境界 | 入力・型・長さ・境界が正しく扱われる | 型変換、off-by-one、NULL、マルチバイト | バリデーション仕様 | ◎ |
| **E** | 異常系・回復性 | エラー・障害が安全に処理され復旧する | 500、無限ループ、データ半端、ロールバック欠如 | エラー設計 / 障害想定 | ○ |
| **S** | セキュリティ | 既知の攻撃クラスに耐える | XSS、SQLi、CSRF、パストラバーサル、任意ファイル実行、SSRF | OWASP / セキュリティ設計 | ○（ペンテスト非機械） |
| **I** | 相互運用性/契約 | API/MCP/CSV の契約が安定・厳密 | 破壊的変更、型不一致、エラー形式不統一、契約逸脱 | `Docs/API.md` / MCP 仕様 | ◎ |
| **U** | 使用性/UX | 迷わず・誤らず・快適に使える | 分かりにくい、誤操作、フィードバック欠如、崩れ | ユーザビリティ原則 / 実ユーザ | ×（非機械） |
| **Y** | アクセシビリティ | 多様な利用者・環境で使える | コントラスト不足、キーボード操作不能、alt 欠落、見出し階層破綻 | WCAG 2.2 AA | △ |
| **P** | 性能/拡張性 | 応答・資源が許容範囲 | 遅延、N+1、OOM、肥大応答 | 性能目標 | ○ |
| **R** | 信頼性/並行性 | 同時実行・再実行・中断で壊れない | 競合、ロスト更新、二重登録、非冪等 | 不変条件 | △ |
| **O** | 運用性/移行性 | 導入・更新・復旧・監視が安全 | インストール失敗、移行データ欠落、復旧不能 | 運用手順 / 移行設計 | ○ |
| **M** | 保守性 | コードが健全で品質ゲートを満たす | 型エラー、lint 違反、循環依存、重複 | phpstan/psalm/phpcs | ◎ |

> **非機械的観点（U / Y の一部 / Z の濫用 / S のペンテスト / R / P の実負荷 / E のカオス）は `05-e2e-exploratory.md` で人間主導として設計する。** これが本計画の「機械的検証にとどまらない E2E」の中核。

## 4. 軸 C: 技法

| コード | 技法 | 概要 |
|---|---|---|
| EQ | 等価分割 | 入力/状態を同値クラスに分けて代表値を選ぶ |
| BV | 境界値分析 | 最小/最大/±1/空/NULL/型境界 |
| DT | デシジョンテーブル | 条件の組合せ（ロール × 状態 × kind など） |
| ST | 状態遷移 | 未ログイン→ログイン→受験→完了、トークン発行→失効 など |
| PW | ペアワイズ | 多因子の 2 因子網羅（ブラウザ × 種別 × ロール等） |
| UC | ユースケース | 業務フロー単位のシナリオ |
| EG | エラー推測 | 経験に基づく異常入力・操作順序 |
| EX | 探索的（SBTM） | 時間制・チャーター駆動の非機械的探索 |
| AB | 濫用ケース | 攻撃者視点のビジネスロジック悪用 |
| PB | プロパティベース | 不変条件（例: 集計=明細和）を入力生成で検証 |
| FZ | ファジング | ランダム/大量/不正入力の投入 |
| RG | 回帰 | 既存 626 項目の再実行 |
| SM | スモーク | デプロイ直後の主要動線の短時間確認 |
| CH | カオス | 障害注入（DB 断、ディスク満杯、タイムアウト） |
| PF | 性能/負荷 | 同時実行・大量データ・長期稼働 |
