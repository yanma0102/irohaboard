# 画面操作・UIインタラクション検証（UI Operation）

> 上位: `README.md` / 画面一覧: `07-screen-inventory-matrix.md` / 観点: `01-verification-perspective-matrix.md` / E2E: `05-e2e-exploratory.md`

---

## 0. 位置づけと目的

`02`〜`04` は「機能が正しいか（What）」を、`05` は「業務が通るか（Journey）」を検証する。本ドキュメントはその間を埋める **「実際のブラウザで人間がどう操作し、どう感じるか（How）」** を体系的に検証する。

- 目的1: 画面操作に固有の不良（操作不能、誤操作、フィードバック欠如、状態破綻）を検出する。
- 目的2: JavaScript 依存の動的 UI（並べ替え・リッチエディタ・モーダル・Select2）を実機で確認する。
- 目的3: `07` の全画面（SCR-F-01〜19 / SCR-A-01〜20）に操作シナリオを与える。

## 1. 原則（機械的検証にとらわれない）

1. **実ブラウザ・実ポインタで操作する**。HTTP クライアント（curl/PHPUnit）の成功は操作検証の代替にならない。
2. **操作の前後で「何が起きたか」を観察する**（見た目・フォーカス・スクロール・トースト/エラー・URL・戻る挙動）。合否だけでなく違和感・遅延・二度手間を記録する。
3. **壊しに行く**。連打・中断・戻る・二重タブ・JS 無効・低速・不正値など、設計者が想定しない操作を試す。
4. **人間判断を残す**。期待結果に「分かりやすい」「迷わない」等が含まれる項目は `機械=難` とし、探索チャーター（`05`）と接続する。
5. **証跡は画面録画/スクリーンショット/コンソールログ**で残す（DOM スナップショットではなく「操作の記録」）。

---

## 2. 実施方法

- 対象: `07` の全画面。ブラウザは Chrome を主、Firefox/Safari/Edge を §6 で併用。
- 端末: デスクトップ（1920×1080 / 1366×768）とモバイル（375×667 / 390×844、実機または DevTools エミュレーション）。
- 記録: 各項目の「結果/証跡」に `□/OK/NG/N/A` + スクリーンショット名 + 使用ブラウザ/端末を記入。不良は `06` の重大度 `S1`〜`S4` と `05` §重大度で分類する。
- 自動化可能なものは `機械=可`。Playwright 導入後は対象化する（`06` 自動化ロードマップ）。

## 5. 実施手順・証跡・判定

1. `07` の画面IDごとに §4 のシナリオを 1 巡し、§3 の該当 VR-UI を実施する。
2. 各実施で「操作ログ（何をしたか）」「観察（何が起きたか）」「証跡（画像/録画/コンソール）」を残す。
3. 不良は再現手順・期待・実際・環境（ブラウザ/端末/回線）を添えて `S1`〜`S4` を付す。
4. `機械=難` の項目は `05` の探索チャーター（CH-16/17/18/24/26/27 等）として時間制で実施し、セッションシートに記録する。
